# Requirements Baseline: CHG-20261115-001-harness-workflow

## Goal

Ensure all future software requests use a complete, traceable, risk-adjusted Harness workflow.

## Acceptance criteria

- [x] Every request receives a Change ID and summary.
- [x] Simple work has a four-step quick flow.
- [x] Planned work has design review, code review, and CI acceptance.
- [x] Complex work has risk review, release approval, and post-release review.
- [x] Human approval points are explicit.
- [x] Each completed Change records lessons and reusable memory.
- [x] Current application runtime behavior is not changed.
